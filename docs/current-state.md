## Known Limitations Currently Accepted

*(Mirror the high-level summary here; full detail lives in known-issues.md. Keep this list short — just enough to orient a new session.)*

- MediaPipe is pinned to `mediapipe==0.10.21` in `requirements.txt` because 1.0.0 (and 0.10.35 here) removed the legacy `solutions.face_detection` API that `core/face_detector.py` uses per D5. See ISSUE-001 (resolved).
- Angled/partial faces may be missed by the face detector (observed: 0 detected on `tests/assets/angled_face.jpg`). Accepted v1 limitation per TESTING.md 3.1 — see ISSUE-002.
- With OCR frame-sampling (`ocr_sample_rate > 1`), PII that moves/scrolls or appears-and-vanishes between samples can be missed or lag its box — accepted v1 tradeoff per TESTING.md 3.2, see ISSUE-003. Lower the sample rate (→ `1`) to trade speed for coverage; faces and static zones are unaffected (every frame).
- The Results **Original** preview serves the uploaded file as-is, so it renders in-browser only for browser-supported source codecs; mp4v sample fixtures (`tests/sample_videos/*.mp4`) show controls-but-blank in HTML5 `<video>` though they download/play externally. The **processed** output is always browser-playable H.264. Accepted v1 limitation — see ISSUE-005.
- When an OCR box mixes a label and a PII value, only the value is redacted, but the value's bbox is a **proportional per-line approximation** (RapidOCR gives per-line, not per-glyph, boxes) — with variable-width fonts the redaction edge can be a few pixels off, though it always stays inside the OCR box and always fully covers the value. Accepted v1 limitation — see ISSUE-006.
- Fake-data replacement approximates but does not reproduce the source: text colour and glyph height are **heuristic estimates** (k-means / contour trace) and the replacement is always drawn in `FONT_HERSHEY_SIMPLEX`, not the original font, so it is **not** seamless or font-exact (by design — no GAN/diffusion, D24). Classical inpainting (TELEA/NS) can smear on textured/non-flat backgrounds. At `ocr_sample_rate=1` OCR reruns every frame, so the randomized fake value regenerates per frame and visibly flickers; persistence (D18) only stabilizes it *between* samples when the rate is `>1`. Accepted v1 limitation — see ISSUE-007.
- Face mask geometry is derived from 2D bounding boxes and uses proportional expansion to cover the forehead and chin. It assumes a frontal or semi-frontal face and may misalign on extreme angles or partial occlusions. Accepted v1 limitation — see ISSUE-008.
