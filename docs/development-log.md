# development-log.md

Internal, chronological, short. One entry per session/significant change. This is breadcrumbs for future agents/sessions, not a narrative — a few lines per entry, not paragraphs. If you're writing more than 4-5 lines for one entry, it belongs in `docs/DECISIONS.md` (if it's a reasoned decision) or `docs/known-issues.md` (if it's a problem), not here.

## Format

```
## YYYY-MM-DD — <one-line summary>
- Changed: <file(s)>
- Why: <one line>
- Commit: <git hash or "uncommitted">
```

## 2026-08-05 — Bug fix: redact only the PII value inside a label+value OCR box
- Changed: core/pii_matcher.py (new `find_pii()` returning `(type, start, end, value)` spans via `finditer`, `_MATCH_PRECEDENCE` for overlap resolution; `is_*()` unchanged), core/video_pipeline.py (new `_span_to_bbox()`; OCR-sampling loop iterates `find_pii()` and redacts each value's tightened sub-bbox; removed now-unused `_classify_pii`/`_PII_CLASSIFIERS`; docstring), tests/test_pii_matcher.py (+TestFindPii, +10), tests/test_video_pipeline.py (+TestValueOnlyRedaction, +11); docs/current-state.md, tasks.md, known-issues.md (ISSUE-006), development-log.md
- Why: OCR returns one box per line, so a box holds "Email: john.doe@example.com". `_classify_pii()` returned only the PII type (the `is_*()` matchers `.search()` and discard the position), and the pipeline blurred/covered the **whole OCR bbox** — erasing the label too. The match span existed in `pii_matcher` but never reached the redactor.
- Result: `find_pii()` exposes each value's character span; `_span_to_bbox()` maps it to a tighter horizontal region of the OCR box (proportional char position, deterministic, bounded, y/h preserved) so only the value is redacted and the label stays visible — both blur and fake-data modes. Value-only boxes yield the original bbox integer-exact (all prior tests hold); multiple values per box each get a region; separate label/value boxes still work; tightened bbox persists between OCR samples and drives fake-data cover. No OCR/face/zone/audio/H.264 change; no new dependency. Focused → **82 passed, 70 subtests**; full `python -m pytest tests/test_*.py` → **234 passed, 100 subtests** (was 213; +21), no regressions. Real-video (`test_mixed.mp4`): single OCR box `(445,98,345,32)` for "Email: …" → label sharpness retained 100% / value 0% (blur); label mean|Δ| 3.23 / value 57.75 and output label OCR reads `Email:` (fake-data).
- Note: documented approximation ISSUE-006 — RapidOCR gives per-line, not per-glyph, boxes, so `_span_to_bbox` assumes uniform char width (value edge can be a few px off with proportional fonts; always stays inside the box and covers the value). No DECISIONS.md entry — no architectural fork; the additive span API is the obvious minimal fix.
